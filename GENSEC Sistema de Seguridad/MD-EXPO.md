## 1. 🎭 **FACADE PATTERN** - Simplificando la Complejidad

### **¿Por qué lo usamos?**
Un sistema antivirus tiene docenas de componentes complejos (detectores, monitores, handlers, configuración, ML models, etc.). Sin un patrón Facade, cada cliente tendría que conocer y manejar toda esta complejidad interna.

### **Beneficios:**
- ✅ **Interfaz simplificada** para operaciones complejas
- ✅ **Desacoplamiento** entre clientes y subsistemas
- ✅ **Punto único de entrada** al sistema
- ✅ **Facilita testing** y mantenimiento

### **Implementación en nuestro sistema:**

#### **✅ CON Facade Pattern (Nuestro código):**

```python
# core/engine.py - UnifiedAntivirusEngine (Facade)
class UnifiedAntivirusEngine:
    """
    Facade que simplifica el acceso a todo el sistema antivirus
    """
    def __init__(self):
        self.plugin_manager = PluginManager()
        self.event_bus = EventBus()
        self.config_manager = ConfigManager()
        self.ml_engine = MLEngine()
        self.quarantine_manager = QuarantineManager()
        self.threat_intelligence = ThreatIntelligence()
        
    def start_protection(self):
        """Inicia protección completa con una sola llamada"""
        try:
            # Operaciones complejas internas simplificadas
            self.config_manager.load_all_configs()
            self.plugin_manager.discover_and_load_plugins()
            self.ml_engine.load_models()
            self.event_bus.start_event_processing()
            self.threat_intelligence.update_signatures()
            
            # Iniciar todos los plugins de forma coordinada
            for plugin in self.plugin_manager.get_active_plugins():
                plugin.initialize()
                plugin.start()
                
            self.logger.info("🛡️ Protección antivirus iniciada exitosamente")
            return True
            
        except Exception as e:
            self.logger.error(f"Error iniciando protección: {e}")
            return False
    
    def stop_protection(self):
        """Detiene protección completa con una sola llamada"""
        for plugin in self.plugin_manager.get_active_plugins():
            plugin.stop()
        self.event_bus.stop()
        
    def get_system_status(self):
        """Obtiene estado completo del sistema simplificado"""
        return {
            'active_plugins': len(self.plugin_manager.get_active_plugins()),
            'threats_detected': self.get_threat_count(),
            'system_health': self.get_health_status(),
            'uptime': self.get_uptime()
        }

# Uso desde el cliente (production_launcher.py)
def main():
    # ¡Una sola línea para iniciar todo el sistema!
    antivirus = UnifiedAntivirusEngine()
    
    if antivirus.start_protection():
        print("✅ Sistema antivirus iniciado")
        
        # Operaciones simples para el usuario
        status = antivirus.get_system_status()
        print(f"Plugins activos: {status['active_plugins']}")
```

## 2. 👁️ **OBSERVER PATTERN** - Comunicación Desacoplada

### **¿Por qué lo usamos?**
En un sistema antivirus, múltiples componentes necesitan reaccionar a eventos (detección de amenazas, cambios de configuración, etc.). Sin Observer, tendríamos acoplamiento fuerte entre todos los componentes.

### **Beneficios:**
- ✅ **Desacoplamiento** entre publicadores y suscriptores
- ✅ **Comunicación asíncrona** entre componentes
- ✅ **Extensibilidad** - fácil agregar nuevos observadores
- ✅ **Separación de responsabilidades**

### **Implementación en nuestro sistema:**

#### **✅ CON Observer Pattern (Nuestro código):**

```python
# core/event_bus.py - Observer Pattern Implementation
class EventBus:
    """
    Event Bus que implementa Observer Pattern
    Permite comunicación desacoplada entre componentes
    """
    def __init__(self):
        self._observers = defaultdict(list)  # event_type -> [observers]
        self._event_queue = queue.Queue()
        self._running = False
        
    def subscribe(self, event_type: str, observer: callable):
        """Suscribe un observador a un tipo de evento"""
        self._observers[event_type].append(observer)
        self.logger.debug(f"Observer suscrito a {event_type}")
        
    def unsubscribe(self, event_type: str, observer: callable):
        """Desuscribe un observador"""
        if observer in self._observers[event_type]:
            self._observers[event_type].remove(observer)
            
    def publish(self, event_type: str, event_data: dict):
        """Publica un evento a todos los observadores suscritos"""
        event = {
            'type': event_type,
            'data': event_data,
            'timestamp': datetime.now(),
            'id': str(uuid.uuid4())
        }
        
        # Notificación asíncrona - no bloquea al publicador
        self._event_queue.put(event)
        
    def _process_events(self):
        """Procesa eventos de la cola (ejecuta en thread separado)"""
        while self._running:
            try:
                event = self._event_queue.get(timeout=1)
                event_type = event['type']
                
                # Notifica a TODOS los observadores suscritos
                for observer in self._observers[event_type]:
                    try:
                        # Llamada asíncrona - no bloquea otros observadores
                        threading.Thread(
                            target=observer,
                            args=(event,),
                            daemon=True
                        ).start()
                    except Exception as e:
                        self.logger.error(f"Error en observer: {e}")
                        
            except queue.Empty:
                continue

# Uso en detectores (observer/subscriber)
```

## 3. 🏭 **FACTORY PATTERN** - Creación Dinámica de Componentes

### **¿Por qué lo usamos?**
Nuestro sistema debe cargar plugins dinámicamente sin conocer sus tipos específicos en tiempo de compilación. Factory Pattern nos permite crear instancias basadas en configuración.

### **Beneficios:**
- ✅ **Creación dinámica** de objetos
- ✅ **Desacoplamiento** de la lógica de creación
- ✅ **Extensibilidad** - fácil agregar nuevos tipos
- ✅ **Configuración flexible**

### **Implementación en nuestro sistema:**

#### **✅ CON Factory Pattern (Nuestro código):**

```python
# core/plugin_manager.py - Factory Pattern Implementation
class PluginFactory:
    """
    Factory para crear plugins dinámicamente
    """
    def __init__(self):
        self._plugin_registry = {}
        self._plugin_configs = {}
        
    def register_plugin(self, plugin_type: str, plugin_class: type):
        """Registra un tipo de plugin"""
        self._plugin_registry[plugin_type] = plugin_class
        
    def create_plugin(self, plugin_type: str, config: dict = None):
        """Crea una instancia de plugin dinámicamente"""
        if plugin_type not in self._plugin_registry:
            raise ValueError(f"Plugin type '{plugin_type}' not registered")
            
        plugin_class = self._plugin_registry[plugin_type]
        
        try:
            # Creación dinámica con configuración
            plugin_instance = plugin_class(config or {})
            
            # Configuración común a todos los plugins
            plugin_instance.set_event_bus(self.event_bus)
            plugin_instance.set_logger(self.logger)
            
            return plugin_instance
            
        except Exception as e:
            self.logger.error(f"Error creating plugin {plugin_type}: {e}")
            return None
            
    def get_available_plugins(self):
        """Retorna lista de plugins disponibles"""
        return list(self._plugin_registry.keys())

class PluginManager:
    """
    Gestor de plugins que usa Factory Pattern
    """
    def __init__(self):
        self.factory = PluginFactory()
        self.active_plugins = {}
        
    def discover_and_load_plugins(self):
        """Descubre y carga plugins automáticamente"""
        plugin_configs = self._load_plugin_configs()
        
        for plugin_config in plugin_configs:
            plugin_type = plugin_config['type']
            plugin_name = plugin_config['name']
            
            # ¡Creación dinámica usando Factory!
            plugin = self.factory.create_plugin(plugin_type, plugin_config)
            
            if plugin:
                self.active_plugins[plugin_name] = plugin
                self.logger.info(f"✅ Plugin '{plugin_name}' loaded successfully")
            else:
                self.logger.error(f"❌ Failed to load plugin '{plugin_name}'")
                
    def _load_plugin_configs(self):
        """Carga configuraciones de plugins desde JSON"""
        with open('config/plugins_config.json', 'r') as f:
            config = json.load(f)
            
        return config['plugins']
```

## 4. 🎯 **STRATEGY PATTERN** - Múltiples Algoritmos de Detección

### **¿Por qué lo usamos?**
Diferentes tipos de amenazas requieren diferentes estrategias de detección. Strategy Pattern nos permite cambiar algoritmos dinámicamente sin modificar el código cliente.

### **Beneficios:**
- ✅ **Intercambio dinámico** de algoritmos
- ✅ **Extensibilidad** - fácil agregar nuevas estrategias
- ✅ **Separación de responsabilidades**
- ✅ **Testing independiente** de cada estrategia

### **Implementación en nuestro sistema:**

#### **✅ CON Strategy Pattern (Nuestro código):**

```python
# core/interfaces.py - Strategy Interface
from abc import ABC, abstractmethod

class DetectionStrategy(ABC):
    """Interfaz común para todas las estrategias de detección"""
    
    @abstractmethod
    def detect(self, data: dict) -> dict:
        """Detecta amenazas usando estrategia específica"""
        pass
        
    @abstractmethod
    def get_confidence_threshold(self) -> float:
        """Retorna umbral de confianza para esta estrategia"""
        pass

# Estrategias concretas de detección
class MLDetectionStrategy(DetectionStrategy):
    """Estrategia de detección usando Machine Learning"""
    
    def __init__(self, model_path: str):
        self.model = self._load_onnx_model(model_path)
        self.feature_extractor = FeatureExtractor()
        
    def detect(self, data: dict) -> dict:
        """Detección usando modelo ONNX"""
        try:
            # Extracción de características
            features = self.feature_extractor.extract(data)
            
            # Predicción con modelo ML
            prediction = self.model.run(None, {'input': features})[0]
            confidence = float(prediction[0])
            
            return {
                'is_threat': confidence > self.get_confidence_threshold(),
                'confidence': confidence,
                'strategy': 'ML',
                'details': {
                    'model_version': self.model.get_metadata(),
                    'features_used': len(features)
                }
            }
        except Exception as e:
            return {'error': str(e), 'strategy': 'ML'}
            
    def get_confidence_threshold(self) -> float:
        return 0.85

class BehaviorAnalysisStrategy(DetectionStrategy):
    """Estrategia de detección por análisis de comportamiento"""
    
    def __init__(self, rules_path: str):
        self.rules = self._load_behavior_rules(rules_path)
        self.behavior_tracker = BehaviorTracker()
        
    def detect(self, data: dict) -> dict:
        """Detección basada en reglas de comportamiento"""
        process_behavior = self.behavior_tracker.analyze(data)
        
        threat_score = 0.0
        triggered_rules = []
        
        for rule in self.rules:
            if rule.matches(process_behavior):
                threat_score += rule.weight
                triggered_rules.append(rule.name)
                
        confidence = min(threat_score / 10.0, 1.0)  # Normalizar a 0-1
        
        return {
            'is_threat': confidence > self.get_confidence_threshold(),
            'confidence': confidence,
            'strategy': 'Behavior',
            'details': {
                'triggered_rules': triggered_rules,
                'behavior_score': threat_score
            }
        }
        
    def get_confidence_threshold(self) -> float:
        return 0.7

class SignatureDetectionStrategy(DetectionStrategy):
    """Estrategia de detección por firmas/signatures"""
    
    def __init__(self, signatures_db: str):
        self.signatures = self._load_signatures(signatures_db)
        
    def detect(self, data: dict) -> dict:
        """Detección basada en firmas conocidas"""
        file_hash = data.get('file_hash')
        process_name = data.get('process_name', '').lower()
        
        # Verificar hash en base de datos de firmas
        if file_hash in self.signatures['malicious_hashes']:
            return {
                'is_threat': True,
                'confidence': 1.0,
                'strategy': 'Signature',
                'details': {
                    'match_type': 'hash',
                    'signature_id': self.signatures['malicious_hashes'][file_hash]
                }
            }
            
        # Verificar nombres de procesos sospechosos
        for suspicious_name in self.signatures['suspicious_names']:
            if suspicious_name in process_name:
                return {
                    'is_threat': True,
                    'confidence': 0.9,
                    'strategy': 'Signature',
                    'details': {
                        'match_type': 'process_name',
                        'matched_pattern': suspicious_name
                    }
                }
                
        return {'is_threat': False, 'confidence': 0.0, 'strategy': 'Signature'}
        
    def get_confidence_threshold(self) -> float:
        return 0.8

# Context que usa las estrategias
class KeyloggerDetector(BasePlugin):
    """Context que utiliza diferentes estrategias dinámicamente"""
    
    def __init__(self, config: dict):
        super().__init__(config)
        self.strategies = {}
        self._load_strategies()
        
    def _load_strategies(self):
        """Carga estrategias basadas en configuración"""
        config = self.config.get('detection_strategies', {})
        
        if config.get('ml_enabled', True):
            self.strategies['ml'] = MLDetectionStrategy(
                config.get('ml_model_path', 'models/keylogger_model.onnx')
            )
            
        if config.get('behavior_enabled', True):
            self.strategies['behavior'] = BehaviorAnalysisStrategy(
                config.get('behavior_rules', 'config/behavior_rules.json')
            )
            
        if config.get('signature_enabled', True):
            self.strategies['signature'] = SignatureDetectionStrategy(
                config.get('signatures_db', 'threat_intel/signatures.db')
            )
    
    def detect_threat(self, data: dict) -> dict:
        """Usa múltiples estrategias para detección"""
        results = {}
        max_confidence = 0.0
        final_decision = False
        
        # Ejecuta TODAS las estrategias habilitadas
        for strategy_name, strategy in self.strategies.items():
            result = strategy.detect(data)
            results[strategy_name] = result
            
            if result.get('confidence', 0) > max_confidence:
                max_confidence = result['confidence']
                
            if result.get('is_threat', False):
                final_decision = True
                
        # Decisión final basada en consenso de estrategias
        return {
            'is_threat': final_decision,
            'max_confidence': max_confidence,
            'strategy_results': results,
            'detection_time': datetime.now().isoformat()
        }
        
    def switch_strategy(self, strategy_name: str):
        """Cambia estrategia dinámicamente (para testing)"""
        if strategy_name in self.strategies:
            self.current_strategy = self.strategies[strategy_name]
            self.logger.info(f"Switched to {strategy_name} detection strategy")
```

## 5. 📋 **TEMPLATE METHOD PATTERN** - Ciclo de Vida Común

### **¿Por qué lo usamos?**
Todos los plugins tienen un ciclo de vida similar (initialize → start → process → stop), pero cada uno implementa estos pasos de manera diferente. Template Method define el esqueleto común.

### **Beneficios:**
- ✅ **Consistencia** en el ciclo de vida
- ✅ **Reutilización** del código común
- ✅ **Flexibilidad** en implementaciones específicas
- ✅ **Mantenimiento centralizado**

### **Implementación en nuestro sistema:**

#### **✅ CON Template Method Pattern (Nuestro código):**

```python
# core/base_plugin.py - Template Method Implementation
from abc import ABC, abstractmethod

class BasePlugin(ABC):
    """
    Template Method que define el ciclo de vida común de todos los plugins
    """
    
    def __init__(self, config: dict):
        self.config = config
        self.logger = None
        self.event_bus = None
        self._is_initialized = False
        self._is_running = False
        
    # TEMPLATE METHOD - Define el algoritmo común
    def start_plugin(self) -> bool:
        """
        Template method que define el proceso completo de inicio
        """
        try:
            self.logger.info(f"🚀 Starting plugin: {self.__class__.__name__}")
            
            # Paso 1: Validación común
            if not self._validate_config():
                self.logger.error("❌ Config validation failed")
                return False
                
            # Paso 2: Pre-inicialización común
            self._setup_common_resources()
            
            # Paso 3: Inicialización específica (abstracto - subclases lo implementan)
            if not self.initialize():
                self.logger.error("❌ Plugin initialization failed")
                return False
                
            self._is_initialized = True
            
            # Paso 4: Setup de eventos común
            self._setup_event_subscriptions()
            
            # Paso 5: Inicio específico (abstracto - subclases lo implementan)
            if not self.start():
                self.logger.error("❌ Plugin start failed")
                return False
                
            self._is_running = True
            
            # Paso 6: Post-inicio común
            self._register_metrics()
            
            self.logger.info(f"✅ Plugin started successfully: {self.__class__.__name__}")
            return True
            
        except Exception as e:
            self.logger.error(f"💥 Error starting plugin: {e}")
            return False
    
    def stop_plugin(self):
        """Template method para detener plugin"""
        if not self._is_running:
            return
            
        try:
            self.logger.info(f"🛑 Stopping plugin: {self.__class__.__name__}")
            
            # Paso 1: Cleanup específico
            self.cleanup()
            
            # Paso 2: Cleanup común
            self._cleanup_common_resources()
            self._unregister_metrics()
            
            self._is_running = False
            self.logger.info(f"✅ Plugin stopped: {self.__class__.__name__}")
            
        except Exception as e:
            self.logger.error(f"💥 Error stopping plugin: {e}")
    
    # MÉTODOS COMUNES (implementados en clase base)
    def _validate_config(self) -> bool:
        """Validación común de configuración"""
        required_fields = self.get_required_config_fields()
        
        for field in required_fields:
            if field not in self.config:
                self.logger.error(f"Missing required config field: {field}")
                return False
                
        return True
        
    def _setup_common_resources(self):
        """Setup común de recursos"""
        self.start_time = datetime.now()
        self.metrics = {
            'events_processed': 0,
            'threats_detected': 0,
            'errors_occurred': 0
        }
        
    def _setup_event_subscriptions(self):
        """Setup común de suscripciones a eventos"""
        if self.event_bus:
            # Cada plugin se suscribe a eventos de su interés
            for event_type in self.get_subscribed_events():
                self.event_bus.subscribe(event_type, self._handle_event)
                
    def _handle_event(self, event):
        """Handler común de eventos"""
        try:
            self.metrics['events_processed'] += 1
            result = self.process_event(event)
            
            if result and result.get('is_threat'):
                self.metrics['threats_detected'] += 1
                
        except Exception as e:
            self.metrics['errors_occurred'] += 1
            self.logger.error(f"Error processing event: {e}")
            
    # MÉTODOS ABSTRACTOS (subclases DEBEN implementarlos)
    @abstractmethod
    def initialize(self) -> bool:
        """Inicialización específica del plugin"""
        pass
        
    @abstractmethod
    def start(self) -> bool:
        """Inicio específico del plugin"""
        pass
        
    @abstractmethod  
    def cleanup(self):
        """Cleanup específico del plugin"""
        pass
        
    @abstractmethod
    def process_event(self, event: dict) -> dict:
        """Procesamiento específico de eventos"""
        pass
        
    # HOOKS OPCIONALES (subclases pueden sobrescribirlos)
    def get_required_config_fields(self) -> list:
        """Campos de configuración requeridos"""
        return ['enabled']
        
    def get_subscribed_events(self) -> list:
        """Eventos a los que se suscribe este plugin"""
        return []
```

| **Consistencia** | Inconsistente - cada plugin maneja errores diferente | Consistente - mismo ciclo de vida |
| **Testing** | Testing duplicado para lógica común | Testing centralizado |
| **Tiempo de desarrollo** | Semanas para nuevo plugin | Horas para nuevo plugin |
